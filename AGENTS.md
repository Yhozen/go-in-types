# go-in-types

Go programs compiled ahead of time to TypeScript type aliases and run by the
type checker (tsrs). Read `docs/PLAN.md` and `docs/LESSONS.md` first; once it
exists, `docs/DESIGN.md` is the contract.

## Layout

- `vendor/typescript`: submodule, github.com/microsoft/TypeScript at tag
  v7.0.2 (the Go compiler is in `vendor/typescript/tsc`, module
  `github.com/microsoft/typescript-go`). Read only; changes go in Go
  overlays under `overlay/` (`go build -overlay`), never in the submodule.
- `frontend/`: the Go front end (source → SSA → IR JSON). Build time only.
- `src/`: TypeScript (IR types, reference interpreter, type-level runtime,
  emitter).
- `experiments/`: measurement scripts (stage 0); `docs/stage0/`: results.
- `.run/`: scratch, git-ignored (e.g. the instrumented tsrs checkout).

## Rules

- Conventional Commits; end messages with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never push and never add remotes.
- "In types" means tsrs (`TSRS_FAST=1 tsrs --fast`); no tsc or tsgo
  benchmarks of type-level code. The native `tsc` 7.0.2 binary
  (`node_modules/.bin/tsc`) is only the oracle for compiler output.
- An instrumented tsrs build is for diagnosis only; every reported cost is
  also measured on stock tsrs.
- Generated files are marked as such and regenerated by a script.
- At most two heavy tsrs jobs at once on this machine, across all agents.
- Before committing: `vp check --fix`, `vp run check`, `vp test`.

## Vite+

Toolchain is Vite+ (`vp`). `vp install`, `vp check`, `vp test`,
`vp run <script>`. Run TypeScript files with `node file.ts` (Node ≥ 26).
